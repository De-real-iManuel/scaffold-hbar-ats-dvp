# AGENTS.md — scaffold-hbar-ats-dvp

AI agent context for autonomous development in this repository.

## Commands

### Install dependencies
```bash
corepack enable && yarn install
```

### Compile Solidity
```bash
yarn hardhat:compile
# or
cd packages/hardhat && yarn compile
```

### Run Hardhat tests (local EVM, no credentials needed)
```bash
yarn hardhat:test
# or
cd packages/hardhat && yarn test
```

### Type-check all packages
```bash
yarn typecheck
# packages/hardhat: tsc --noEmit
# packages/nextjs: tsc --noEmit
```

### Lint all packages
```bash
yarn lint
```

### Build Next.js frontend
```bash
yarn next:build
# In local mode (no env vars): boots without testnet credentials
```

### Start Next.js dev server
```bash
yarn next:dev
```

### Deploy to Hedera Testnet
```bash
cd packages/hardhat && yarn deploy --network hederaTestnet
```

## Invariants — Never Violate

1. **No committed secrets**: `.env` files are gitignored. No private keys in any tracked file.
2. **No non-IERC20 transfer methods**: `DvPSettlement` must only call `IERC20.transferFrom`. Never `forcedTransfer`, `controllerTransfer`, or any ATS-specific method.
3. **No proxy/upgrade patterns**: `DvPSettlement` is non-upgradeable. Do not add `initialize()`, proxy patterns, or `delegatecall` routes.
4. **No floating-point in on-chain amounts**: All token amounts in the contract and frontend must use `bigint` / `uint256`. Never `parseFloat`, `toFixed`, or `Number()` for amounts.
5. **CEI pattern in acceptOffer**: State update (`status = Filled`) must occur before any external call.
6. **Never catch transfer failures silently**: `require(transferFrom(...))` must be used. No try/catch around token calls.
7. **No secrets in deployment artifacts**: `txHash`, `contractAddress`, and `abi` are allowed in deployment files. Private keys must never appear.

## Secret Handling Rules

| Variable | Where to set | Where it must NEVER appear |
|---|---|---|
| `DEPLOYER_PRIVATE_KEY` | `packages/hardhat/.env` | Logs, deployment artifacts, frontend, git history |
| `ATS_ADMIN_PRIVATE_KEY` | `packages/hardhat/.env` | Same as above |
| `SELLER_PRIVATE_KEY` | `packages/hardhat/.env` | Same as above |
| `BUYER_PRIVATE_KEY` | `packages/hardhat/.env` | Same as above |
| `NEXT_PUBLIC_WC_PROJECT_ID` | `packages/nextjs/.env` | Not a secret but don't commit the actual value |

All `.env` files are excluded by `.gitignore`. Run `git status` before any commit to verify no env files are staged.

## Validation Requirements (Must Pass Before PR Merge)

1. `yarn install` — clean install, no errors
2. `yarn hardhat:test` — all tests pass
3. `yarn typecheck` — zero TypeScript errors in both packages
4. `yarn lint` — zero linting errors
5. `yarn next:build` — Next.js production build succeeds in local mode
6. `.github/workflows/ci.yml` — CI passes on latest commit
7. `grep -r "0x[0-9a-fA-F]\{64\}" packages/ template.json package.json` — zero matches (no committed private keys)

## Harness Note

Kiro is **not** a supported harness backend. The supported backends are Claude Code and Cursor (as documented in [hedera-dev/hedera-harness](https://github.com/hedera-dev/hedera-harness)).

The project's own test suite (`packages/hardhat/test/DvPSettlement.test.ts`) is the authoritative automated validation equivalent. The `.harness/validators/` scripts provide structural checks.
